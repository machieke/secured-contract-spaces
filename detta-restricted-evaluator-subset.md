# DeTTa Restricted Evaluator Subset

This document defines the currently implemented restricted evaluator subset and
the checked-in fixture schemas used to keep evaluator behavior stable.

The production target remains a restricted MeTTa/PeTTa evaluator. The current
`detta-evaluator` crate is the deterministic kernel-facing subset used by DeTTa
tests until a full parser and canonical AST are added.

## Versioning

The evaluator fixtures are versioned independently:

- proof trace fixture schema:
  `detta.restricted-evaluator-proof-trace.v1`;
- forbidden primitive fixture schema:
  `detta.restricted-evaluator-forbidden-primitive.v1`;
- both schemas carry `schema_version: 1`.

Schema-compatible changes may add optional fields only after readers tolerate
them. Field removal, renamed variants, changed enum encodings, or changed root
calculation require a new schema name and schema version.

## Supported Instruction Subset

The current instruction enum is the canonical evaluator IR for this slice:

- `UsePrimitive(EvaluatorPrimitive)` checks whether a primitive is available to
  contract code.
- `StateGet(StateKey)` emits a `TraceOp::StateGet` after passing the primitive
  gate.
- `StateSet(StateKey, StateValue)` emits a `TraceOp::StateSet` after passing
  the primitive gate.
- `CallContract { contract, method }` emits a cross-contract call trace entry
  after passing the primitive gate.
- `PureAdd { left, right }` performs checked unsigned addition and appends the
  value to the execution report.
- `Abort` emits `TraceOp::Abort` and returns `EvaluatorError::Aborted`.

Execution is step-metered. Every instruction consumes one step. If the next
instruction would exceed `max_steps`, execution returns
`EvaluatorError::StepBudgetExceeded`.

## Allowed Primitives

The following `EvaluatorPrimitive` variants are allowed in contract execution:

- `StateGet`
- `StateSet`
- `RegistryGet`
- `RegistrySetGuarded`
- `EmitEvent`
- `CallContract`
- `Abort`
- `PureArithmetic`
- `PureComparison`
- `PureData`

Mutation primitives in this list are not raw host operations. They are only
entrypoints into guarded runtime kernels that enforce method policy, write
scope, registry authority, resource accounting, and atomic commit/revert.

## Forbidden Primitives

The following `EvaluatorPrimitive` variants are forbidden in contract execution:

- `RawAddAtom`
- `RawRemoveAtom`
- `RawPrivateMatch`
- `PrologAssert`
- `PrologRetract`
- `PythonCall`
- `FileSystemAccess`
- `ProcessExecution`
- `NetworkAccess`
- `WallClockAccess`
- `Randomness`
- `ArbitraryImport`

Each forbidden primitive must return `EvaluatorError::ForbiddenPrimitive` before
performing host or Atomspace effects.

## Proof Trace Fixture

`models/detta-restricted-evaluator-proof-trace.json` has this schema:

- `schema`: schema identifier;
- `schema_version`: numeric schema version;
- `evaluator`: evaluator implementation identifier;
- `max_steps`: step budget used by the fixture;
- `script`: canonical instruction sequence;
- `report`: emitted trace, pure values, and steps used;
- `trace_root`: SHA-256 of the compact JSON serialization of `report.trace`;
- `symbolic_verifier`: contract id, allowed write scope, and verifier errors.

The fixture is generated by
`detta_evaluator::restricted_evaluator_proof_trace_fixture()`. The evaluator
crate tests that the checked-in JSON exactly matches this function and that the
trace root and symbolic verifier result remain stable.

## Forbidden Primitive Fixture

`models/detta-restricted-evaluator-forbidden-primitives.json` has this schema:

- `schema`: schema identifier;
- `schema_version`: numeric schema version;
- `evaluator`: evaluator implementation identifier;
- `max_steps`: step budget used by each trap script;
- `allowed_primitives`: complete allowed primitive table;
- `forbidden_cases`: every forbidden primitive with the exact one-instruction
  script and expected error.

The fixture is generated by
`detta_evaluator::restricted_evaluator_forbidden_primitive_fixture()`. The
evaluator crate tests that every forbidden escape hatch from the SCS spec is
covered by the checked-in JSON.

## Refresh Workflow

When evaluator behavior changes:

1. Update the fixture builder functions in `crates/detta-evaluator`.
2. Regenerate the affected JSON fixture from the pretty JSON produced by the
   builder.
3. Refresh the matching `.sha256` file with the SHA-256 of the checked-in JSON
   fixture bytes.
4. Run `cargo fmt && cargo test && cargo clippy --all-targets -- -D warnings`.
5. Review the fixture diff as a semantic compatibility change, not as generated
   noise.

Fixture drift without an intentional schema or behavior change is a regression.
